# レビュー指摘を改善へ取り込む

<!-- doc-purpose:start -->
> **役割:** issue・PR・依頼文書の指摘を対象commitで確認し、安全な回帰と差分へつなげる。
>
> **対象読者:** 開発・設計担当
>
> **読むタイミング:** レビュー指摘を再現して修正し、検証根拠を揃えて返すとき。
>
> **前提となる資料:** [変更する人のための読みやすさと検証規約](<../CONTRIBUTING.md>)
>
> **次に読む資料:** [外部レビュー指摘の対応と確認](<REVIEW-FOLLOWUP.md>) / [検証記録](<VALIDATION.md>)
>
> **文書一覧:** [目的・読者から探す文書マニフェスト](<DOCUMENTATION-MANIFEST.md>)
<!-- doc-purpose:end -->

GitHubのissue、PR review、修正依頼文書から、対象commitと根拠を確認して修正します。同時作業では、未コミット変更や他の担当者のcommitを破棄・上書きせず、実際の差分を確認します。

## 指摘に含める情報

| 項目 | 内容 |
| --- | --- |
| 対象 | 公開commit、branch、ファイルと行、必要なprofile |
| 問題 | 再現する操作、実際の結果、期待する結果 |
| 根拠 | 採用版の公式資料・コード・合成試験。推測と事実を分ける |
| 優先度 | 影響、再現条件、データ/互換性/機密への関係 |
| 修正の確認 | 何が通れば解消と判断できるか |

社内URL、実IP、proxy、資格情報、企業CA、業務データ、生ログは掲載しません。必要な再現入力は一般化した最小の合成値にします。図の指摘は図IDとpanel/edge、キャプションの該当箇所も示します。

## 取り込みの順序

1. issue/文書の対象commitと現在のmain・作業branchを照合します。新しいcommitですでに解消している場合は重複修正しません。
2. 指摘を実装・採用版の公式資料・最小再現で確認します。提案に従う場合も、秘密の公開や既存データ破壊を伴う操作は別に扱います。
3. 修正範囲と担当を揃え、他の変更と同じファイルを扱う場合は差分を確認します。無関係な変更をまとめて戻しません。
4. 関連コード、説明、図、期待値を整合させ、必要なテストと公開前の機密検査を実行します。
5. PRへ対応するissue/文書、変更理由、検証結果、未解決点を記載します。未実施の実会社確認やOffice描画を成功扱いにしません。
6. merge直前にもmainと新着reviewを確認します。mainが進んでいれば差分を統合し、影響する検査を再実行します。

図・exportの編集規約は [編集ガイド](reports/EDITING-GUIDE.md)、機密情報の境界は [公式資料・文書監査](REFERENCES.md)、既存の機能検証は [VALIDATION.md](VALIDATION.md) を参照します。作業中の新着確認と、常設の自動監視を区別します。

具体的な指摘・原因・修正・回帰の例は [REVIEW-FOLLOWUP](REVIEW-FOLLOWUP.md) にあります。レビュー文書を読むだけでなく、再現と受入条件を実装へ結び付けます。

## 初めてレビューへ参加する人へ

指摘を一つの操作で説明します。「設定できない」だけではなく、合成設定を用意して実行したコマンド、期待する拒否/成功、実際の表示、対象commitを添えます。実環境の値を隠すために再現性まで失わないよう、同じ条件になる一般化した入力へ置き換えます。

| 判定 | 次の行動 |
| --- | --- |
| 現在のmainでも再現 | 最小の回帰を追加し、修正と一緒に確認 |
| 過去のcommitだけで再現 | 解消したcommitと検査を照合して重複を避ける |
| 仕様との差が不明 | 採用版の公式仕様・実装・実際の入力を揃えて判断 |
| 提案が既存データ/機密へ影響 | 公開可能な再現で検討し、稼働環境を直接変更しない |
| 低優先の保守改善 | 対象と受入条件を明記し、通常動作を維持して改善 |

## 対応完了の確認

issueの受付、修正、ローカル検証、push、CI成功、mergeは別の状態です。完了報告には対象PRとcommit、通った検査、未実施の実機確認を示します。closeを伴うPRではissue番号を対応する修正へ結び付け、merge後のmainにも修正があることを確認します。

文書のリンクだけを修正した場合も、その文書の役割欄・索引・関連ページを更新します。図の仕様変更は生成物との差分、report export変更は文字コード・出力先・metadata・オフラインリンクも見ます。[開発検査](../CONTRIBUTING.md) と [図編集](reports/EDITING-GUIDE.md) を使って影響に合う確認を選びます。
